# M1: one environment shot

**Result:** `projects/m1-rooftops/project.json` (the spec) produces `out/m1-rooftops.mp4`: 5.000 s, exactly 120 frames, 1920x1080 @ 24 fps, plus `out/contact.png` and `out/report.json`. Acceptance test: `node --test tests/e2e/m1.test.ts` (5/5 pass). Unit tests: 32/32.

Checks on the final render: shot-length PASS (120 = 5 s x 24), frame-not-empty PASS (21 frames sampled, min std dev 36.5, 0.000% void/missing-texture), repeatable PASS (frame 60 rendered twice in separate Blender processes gives byte-identical files, and matches the stored frame).

Parallax, measured by cross-correlating image bands between frame 1 and frame 120 (camera moves 5.95 m): clouds 17 px, far city 55 px, mid rows 136 px, near rows ~367 px. Geometry predicts 17 / 55 / 136 / 350. Nearer layers move more, in proportion to 1/depth.

Timing on this machine (i7-10750H, Intel UHD, EEVEE): paint 50 s, full render 497 s (first frame ~96 s shader compile, then ~4 s/frame), encode 20 s.

## What was hard
1. **Krita headless hung forever.** `doc.exportImage()` opens a modal "PNG image" options dialog, so the process sat idle. Found by listing the process's windows (CPU time was flat). Fix: write PNGs with Qt from the layer pixel data and keep batch mode on. Earlier wrong turns: an empty `QT_QPA_PLATFORM` also hangs, `offscreen` segfaults, removing the default layer was a red herring.
2. **Cache corruption from a race.** Two of my own runs shared a temp dir; one deleted the other's PNGs and the survivor committed an entry with `done.json` but no layer files. The cache now records every output file with its size (a hit must match), uses per-process temp dirs and a per-key lock, and has regression tests.
3. **Repeatable check failed for a non-obvious reason.** Pixels were identical; Blender writes Date, RenderTime and the absolute .blend path into PNG text chunks. Render script now disables all stamp metadata. The check now says whether pixels or only file bytes differ.
4. **My own parallax test measured the wrong layer** (a band that straddled the mid layer). The render was right; the test band was fixed and strengthened to assert the full depth ordering.
5. Windows quirks: heredocs in this shell halve backslashes (broke a drawtext font path, caught by reading the file), `rm -rf` is denied, background jobs with `&` outlive their shell.

## Two weakest things in the output
1. **It does not look hand-painted.** Layers are vector-style flat shapes: blobby identical clouds, repetitive rowhouses, no brush texture. The film grain is baked into each layer, so it moves with the layer (swims) instead of flickering like real grain. A better look needs painted textures or an image-model step behind the same `paint` interface (spec section 11).
2. **It is 2.5D, not 3D.** Flat planes at fixed depths give parallax for sideways drift only; there is no occlusion parallax inside a layer, no perspective change for rotation, and the camera is limited by painted edge coverage (about 9.8 m sideways, 6 m up/down at lens 50). Also slow: ~10 minutes for 5 s of video.
